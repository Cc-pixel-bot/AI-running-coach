## 0. 文档说明

### 0.1 本文档要解决的问题

本次目标不是"做一个完整产品"，而是**用一个可演示、可验证核心逻辑的最小闭环，证明这个产品成立**。Demo 必须跑通一条完整链路：

```
建立跑者档案 → 生成并确认训练计划 → 真实 GPS 跑步 → 填写训练反馈 → AI 总结并更新后续计划
```

这条链路对应产品的三个核心主张：

1. **档案驱动**：不是标签匹配模板，而是基于跑者真实身体数据与跑步基础做适配
2. **计划可执行**：不是一张表格，而是能下发的、带强度区间的每日训练课次
3. **闭环可迭代**：每次训练后的真实反馈会**改变**后续计划，而不是只生成一段总结文字

### 0.2 与完整产品（商业文档）的差异

完整商业版本面向 200 万目标用户、包含越野分支、社区社交、饮食管理、会员付费体系。本 Demo **只做**：

- ✅ **四类公路跑目标**：5 公里提升、10 公里提升、半程马拉松、全程马拉松
- ✅ 档案 → 计划 → 训练 → 反馈 → 调整 的完整闭环
- ✅ 真实 GPS 轨迹记录与语音陪跑引导
- ✅ 训练前运动风险筛查（ACSM 预参与筛查）与训练中止标准
- ❌ 越野（UTMB/RunMotion 越野计划依赖爬升、路况与技术地形数据，Demo 无支撑；模板库预留扩展位）
- ❌ 零基础跑走结合（对应 NHS Couch to 5K，Demo 不开放该分支，仅作周期设计参考）
- ❌ 社区、社交、动态、排行榜
- ❌ 饮食、减脂、增肌、体态（跨品类，与核心命题无关）
- ❌ 会员付费、订单、发票、运营后台
- ❌ 教练人工审核、专家内容生产后台

> **关于半马 / 全马在 Demo 中的处理（重要设计决策）**
> 半马（12 周）与全马（20 周）周期远超 Demo 可完整走完的长度。若只做"生成计划"而无法闭环，会让这两类用户变成"看得见走不完"的空功能。
> Demo 采用**"生成即完整交付 + 前置解锁"**方案：
> 1. 计划引擎一次生成完整 12/20 周计划并全部下发（用户可查看全周期）
> 2. 循环验证闭环只跑前 2 周的课次（档案 → 计划 → 训练 → 反馈 → 调整 → 下一课次）
> 3. 从第 3 周起，课次在**完成上一周全部课次**后自动解锁（未完成则不解锁，并提示"本周还有 N 次课未完成"）
> 4. 因此 Demo 中半马/全马用户的可演示闭环 = 前 2 周，机制与 5K/10K 完全一致
> **权衡说明**：这样做的代价是"第 3 周后的真实数据"无法现场演示；收益是四个目标共用一套引擎与一套闭环，Demo 演示时长可控，且产品逻辑完整。

## 1. 产品概述

### 1.1 一句话定位

**给业余公路跑者的 AI 私人跑步教练：一份只为你生成的专业跑步训练计划。**

### 1.2 Demo 要证明的三个论点

| # | 论点 | 如何证明 | 演示时观众应该看到的 |
| --- | --- | --- | --- |
| 1 | 专业性 | 计划遵循周期化训练原理，有明确的强度分布与渐进负荷 | 计划总览中有周目标、强度占比、进阶逻辑解释 |
| 2 | 个性化 | 计划由档案匹配而来，并说明"为什么这样安排" | 每节课都有"适配理由"文案，如"你近 3 月周跑量 15km，因此本周围度控制在 18km" |
| 3 | 闭环性 | 跑完 → 反馈 → 计划真的变了，且改得对 | 同一课次前后对比 + 明确的调整原因 + 调整后的新安排 |

#### 1.3.2 四类用户画像

**画像 A｜短距离成绩提升型（用户基本盘，占比最大）**

| 维度 | 特征 |
| --- | --- |
| 典型年龄 | 28–45 岁（10km 参赛峰值集中在 35–39 岁） |
| 职业分布 | 企业职员 / 管理者 / 机关事业单位（与路跑跑者整体画像一致） |
| 运动基础 | 持续跑步 1 年以上，近 3 个月周均跑量 **10–30km**，每周 3–4 次 |
| 当前水平 | 5km：**男 26–33 分 / 女 31–40 分**（全球中位 男 28:43 / 女 34:42）；10km：**男 52–65 分 / 女 62–80 分**（全国平均 1:05:16） |
| 目标 | 3–6 个月内 **5km/10km 提升 5%–10%**，或跨过田协大众等级线 |
| 核心痛点 | 自己练没章法；配速忽快忽慢；怕受伤；报比赛前不知道怎么练 |
| 付费意愿 | 可接受 128–298 元/年 |
| 设备 | 有智能手机，可能有运动手表（Demo 不接手表数据） |

**画像 B｜半程马拉松完赛型**

| 维度 | 特征 |
| --- | --- |
| 典型年龄 | 30–45 岁 |
| 运动基础 | 已有 10km 基础，周跑量 **20–40km**，已完成过长距离（≥16km） |
| 当前水平 | 半马：**男 1:45–2:15 / 女 2:00–2:40**（全国平均 2:06:20；精英级 男 1:34 / 女 1:49） |
| 目标 | 首次半马**安全完赛**；或把成绩压到 **男 1:50 / 女 2:00** 附近（对应田协大众一级水平区间） |
| 核心痛点 | 不知道 12 周该怎么排；担心中途拉伤；不清楚赛前减量；没有配速策略 |
| 计划周期 | **12 周**（对齐 World Athletics 半马官方计划长度），3 次/周 |

**画像 C｜全程马拉松完赛型**

| 维度 | 特征 |
| --- | --- |
| 典型年龄 | 32–48 岁 |
| 运动基础 | 已有半马基础，周跑量 **30–50km**，能完成 ≥21km 长距离 |
| 当前水平 | 全马：**男 3:45–4:45 / 女 4:15–5:30**（全国平均 4:06:04；精英级 男 3:00 / 女 3:20） |
| 目标 | 首次全马完赛，目标 **男 4:30 / 女 5:00**（对应 B.A.A. Level One 强度档） |
| 核心痛点 | 20 周跨度太长无从下手；怕受伤放弃；不知道赛前 2 周怎么减量 |
| 计划周期 | **20 周**（对齐 B.A.A. 官方 20 周马拉松计划：3 周准备 + 6 周基础 + 9 周专项 + 2 周减量） |
| **风险等级** | **最高**。证据：首次全马跑者重大伤发生率 **8.9%**、轻微伤 **48.5%**（Toresdahl 2020）；纽约马拉松队列训练期受伤率 **38.4%**、比赛日 **14.1%**、总体 **42.6%**，其中过度使用伤随训练推进持续上升（McGrath 等 2024，BMJ Open Sport Exerc Med，n=1049） |

**画像 D｜方法缺乏型（跨 A/B/C 的能力型画像）**

能力水平同 A/B/C，但**没有结构化训练习惯**：不知道周期怎么分、强度怎么排、什么算"够量"、赛前该怎么减量。这类用户产品价值最高（Keep 的"标签匹配标准模板"对他们完全无效），也是 Demo 演示时最有说服力的对象。

#### 1.3.3 目标设定原则

目标成绩需要结合用户当前水平、目标周期与同年龄组标准进行可达性校验。以 10km 45:00 为例，对应配速 4'30"/km，已接近较高水平；相对周跑量 10–30km 的业余跑者属于**跨度较大的目标**，系统应提示风险并给出可达的分阶段方案。

采用**四类目标表述**，并强制走可达性校验：

| 目标类型 | 用户表述 | 系统响应 | 依据 |
| --- | --- | --- | --- |
| T1 相对提升 | "我想把 10km 从 65 分跑到 58 分" | 生成 8 周计划，强度与跑量按提升幅度分配 | 训练可提升幅度 |
| T2 等级锚定 | "我想达到田协大众一级" | 反查该年龄段对应成绩，生成达标路径 | 田协 2025 等级评定办法 |
| T3 完赛型 | "我第一次跑半马，想完赛" | 生成 12 周计划，强度保守、长距离递增、赛前减量 | WA 半马官方计划 |
| T4 体验型 | "我想 5km 完赛，别受伤就行" | 生成 8 周轻松计划，强度占比低、跑走结合可选 | WA 5K 官方计划："How fast you run is not what matters most. What matters most is getting out the door." |

**可达性校验规则（引擎硬拦截，AI 不得绕过）**

| 校验项 | 触发条件 | 系统动作 |
| --- | --- | --- |
| 提升幅度 | 目标成绩比当前最好成绩快 **> 10%** | 提示"跨度偏大"，建议延长周期；用户确认后仍按目标生成，但在计划中标注"高目标，风险自担" |
| 精英级目标 | 目标优于**同年龄组**田协精英级标准 | 提示"该成绩属精英级水平，通常需要专项训练与长期积累"，询问是否改为等级目标或完赛目标 |
| 强度跳跃 | 目标配速 < 当前舒适配速 **> 30 秒/km** | 提示"目标强度高于你当前的舒适强度"，建议先做 8 周基础期 |
| 周跑量倒挂 | 目标周期所需跑量 > 当前周跑量 × 1.5 | 周期自动延长，或提示该目标不可达 |
| 伤病冲突 | 目标周期 > 12 周 且 存在未痊愈伤病 | 提示就医确认（ACSM 预参与筛查要求），并自动改为保守版 |

### 1.4 用户使用场景

- **S1 赛前准备型**：3–12 周后有 5km/10km/半马/全马赛事或测评，希望系统安排训练、赛前减量并避免受伤
- **S2 瓶颈突破型**：5km 长期卡在 28 分钟、10km 卡在 65 分钟，想知道到底哪一环没练到位
- **S3 陪伴坚持型**：一个人跑没人管，需要有反馈、有调整、有人管
- **S4 首次长距离型**：第一次跑半马/全马，最大焦虑是"中途出状况"，需要清晰的强度上限、补给提示与训练中止标准
- **S5 状态波动型**：赛前 3 周开始掉量、掉状态，需要系统识别"过度负荷"并主动降级计划

## 2. Demo 核心流程设计

### 2.1 主流程（Happy Path）

```
┌──────────────┐   ┌──────────────┐   ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
│ ① 建立跑者档案 │→ │ ② 生成并确认  │→ │ ③ 真实GPS跑步 │→ │ ④ 填写训练   │→ │ ⑤ AI总结并   │
│   AI 对话采集  │   │   训练计划    │   │   课次执行    │   │   反馈       │   │   更新计划    │
└──────────────┘   └──────────────┘   └──────────────┘   └──────────────┘   └──────────────┘
      ~3min              ~30s               ~30min              ~1min             ~15s
    生成档案卡        方案总览+适配理由      语音陪跑+轨迹       RPE+疼痛+完成度    总结+变更diff
                                                            └──────── 写回训练引擎 ────────┘
```

### 2.2 流程中的关键设计决策

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| 档案采集方式 | AI 对话 + 图片文字选项卡，而非长表单 | 降低门槛；同时能自然收集"训练条件"这类表单难问的信息 |
| 档案采集必填项 | 12 个关键字段为硬性最低集，其余 AI 追问获取 | 平衡"信息足够算计划"与"不流失用户" |
| 计划确认 | 必须用户显式确认，且展示"匹配依据 + AI 调整项" | 借鉴竞品教训：黑盒计划不可信，用户不会执行 |
| 跑步记录 | 真 GPS（非模拟），必须真跑 | Demo 的可信度核心；也是与"课程播放型"产品的区别 |
| 反馈表单 | 结构化量表为主 + 自由文本为辅 | 结构化才能驱动规则引擎；自由文本交给 LLM 挖信号 |
| 计划更新 | 规则引擎先算出变更，LLM 再写解释 | 保证训练逻辑正确、可回归测试；LLM 负责可读性 |
| **强度处方** | **三锚点：主观用力（主）+ 配速偏移（副）+ 心率区间（第三轨）** | 业余跑者对秒/公里不敏感，且配速受天气地形影响大；官方计划中爱尔兰用 RPE+说话测试、WA/B.A.A. 用配速、ACSM 用心率区——本产品三轨并行，用户按可得信息任选其一 |
| **周期长度** | **直接采用官方周期长度（5K 8 周 / 半马 12 周 / 全马 20 周），不自造、不压缩** | 周期化训练中准备/基础/专项/减量的时间比例本身是有效的；演示时长问题用"按周解锁"解决，而非牺牲训练科学性 |
| **训练前筛查** | **建档阶段强制 ACSM 预参与筛查，命中症状则不生成计划** | 承诺专业训练就必须承担专业训练的安全责任；这也是与通用健身 App 最本质的差异 |
| 变更可见 | 生成「本次变更 diff」，用户确认后生效 | 让"闭环"被看见，而不是黑盒改写 |

### 3.2 明确不做（Out of Scope）

### 3.3 UI 页面与视觉设计要求

#### 3.3.1 设计目标

UI 需要体现“专业、运动、积极、有陪伴感”，整体采用**年轻、强动感、具有速度感的运动风格**，避免做成办公管理、医疗问诊或普通数据后台风格。降低用户开始训练的心理门槛，同时让训练状态、风险提示和下一步操作一眼可见。整体采用移动端优先设计，网站版与 uni-app 移动端保持同一套视觉语言和组件规范。

**运动风格关键词**：速度、爆发、节奏、能量、坚持、突破。

- 使用大号训练数据、粗体数字、动态进度条和明显的训练状态，突出“正在运动”而不是“查看数据”。
- 适度使用斜切形状、速度线、渐变、圆角卡片和局部高亮，营造跑步中的方向感和推进感。
- 首页和训练页应有明显的视觉焦点，优先突出“今天练什么”“当前配速”“完成了多少”和“下一步做什么”。
- 避免大面积复杂插画、过多装饰、过度圆润的儿童化图形和低对比度的浅色界面。
- 视觉动效以轻量、快速、短时为主，例如进度增长、数字跳动、按钮反馈和卡片切换；不使用影响训练操作的复杂动画。

#### 3.3.2 视觉配色

产品主视觉采用**橙色 + 红色**，橙色负责运动活力和主要行动引导，红色负责高强度、风险和需要关注的状态。

| 色彩角色 | 色值 | 使用场景 |
| --- | --- | --- |
| 品牌橙 | `#FF7A00` | 主按钮、进度、训练进行中、主要高亮 |
| 活力橙 | `#FF9F43` | 次级按钮、卡片渐变、热身状态、积极反馈 |
| 品牌红 | `#E53935` | 风险提示、疼痛状态、停止训练、错误反馈 |
| 深红 | `#B71C1C` | 严重风险、强制停止、不可忽略的安全提示 |
| 浅橙背景 | `#FFF3E8` | 训练卡片、热身卡片、提示区域背景 |
| 浅红背景 | `#FFEBEE` | 疼痛、风险和异常状态背景 |
| 主文字 | `#1F2937` | 标题、正文、关键数据 |
| 次文字 | `#6B7280` | 辅助说明、时间、来源信息 |
| 页面背景 | `#F8F9FB` | 页面整体背景，搭配运动数据卡片 |

**配色规则**：

- 主操作按钮使用品牌橙；危险操作使用品牌红，不使用橙色表达危险。
- 红色只用于风险、疼痛、停止、错误等需要用户关注的场景，避免全页面大面积使用。
- 橙色与红色组合时，文字必须使用深色或白色，保证可读性；普通文字与背景的对比度不低于 WCAG AA 要求。
- 不仅依靠颜色表达状态，同时使用图标、文字和状态标签，避免色觉障碍用户无法识别。
- 允许在首页、训练卡和完成反馈中使用橙红渐变，但渐变不用于长段正文或大面积页面背景。

| 页面顺序 | 页面 | 核心内容 | 关键操作 |

#### 3.3.5 响应式与无障碍要求

- 网站版先适配 375px、390px、414px 三类移动端宽度，同时兼容桌面端居中展示。
- uni-app 移动端沿用网站版的颜色、间距、圆角、图标和组件命名，避免二次设计。
- 最小可点击区域不小于 44×44px；重要操作之间保留足够间距，避免误触。
- 页面正文最小字号建议 14px，关键数据建议 24–32px；不使用过细字体。
- 训练中页面保持信息层级稳定，配速、距离、时间和暂停/结束操作始终可见。
- 加载、空状态、错误状态、弱网状态、权限拒绝和训练中断均需有明确页面反馈。

#### 3.3.6 Stitch 与 uni-app 衔接要求

- Stitch 负责生成页面视觉稿、组件样式和页面初始代码，不直接决定业务规则。
- 页面组件命名、颜色变量、间距和状态标签需要整理为统一 Design Token。
- 网站版优先采用 Vue 组件化实现；迁移到 uni-app 时复用页面结构、接口调用和状态逻辑。
- GPS、后台定位、语音、视频和权限等能力由 uni-app 原生插件或平台 API 实现，不能只依赖 Stitch 生成的静态页面。

## 4. 详细功能设计

### A. 建立跑者档案

#### A1 AI 对话式档案采集

**入口**：首次登录后自动进入档案引导页；或首页「完善档案」/「重新测评」。

**交互形态**：单列对话流，AI 提问 + 用户作答。AI 提问时**优先给出图片 + 文字选项卡**（如"你的近 3 个月周均跑量？"→ 图表卡 + 选项），自由输入为次要路径。

**追问树**（Demo 裁剪版，共 7 段 19 问）：

| 段 | AI 提问 | 采集字段 | 输入形式 | 是否必填 |
| --- | --- | --- | --- | --- |
| 1 基础信息 | 你的性别 / 出生年份 | gender, birth_year | 选项卡 | ✅ |
| | 你的身高体重 | height_cm, weight_kg | 数字输入（可带 BMI 提示） | ✅ |
| 2 跑步基础 | 你坚持跑步多久了 | running_years | 选项卡（<3个月/3–6月/6–12月/1–3年/>3年） | ✅ |
| | 近 3 个月你每周大约跑几次 | runs_per_week | 选项卡 + 自定义 | ✅ |
| | 近 3 个月你每周大约跑多少公里 | weekly_km | 选项卡（<10/10–20/20–30/30–50/>50） | ✅ |
| | 你最长一次连续跑多远 | longest_run_km | 选项卡 + 自定义 | ✅ |
| 3 既往成绩 | 你跑过哪些距离？（可多选） | race_history（5K/10K/HM/Marathon/无） | 多选卡 | ✅ |
| | 你最好的 5km 成绩 | best_5k_pace | 输入（可"不知道"） | ⭕ |
| | 你最好的 10km 成绩 | best_10k_pace | 输入 | ⭕ |
| | 你最好的一次半马 / 全马成绩 | best_hm_pace / best_mar_pace | 输入 | ⭕ |
| | 你平时的舒服配速（不冲刺） | easy_pace | 输入 / 由 AI 按成绩推算并让用户确认 | ✅ |
| 4 目标 | 你的目标是？ | target_type | 选项卡：**提升 5km / 提升 10km / 半马完赛 / 全马完赛** | ✅ |
| | 目标日期 / 是否有比赛 | target_date, has_race | 日期选择 + 有无比赛 | ✅ |
| | 目标成绩 | target_pace | 输入 / 一键采纳 AI 按等级线给的建议值（见 §1.3.3） | ✅ |
| 5 身体与条件 | 膝/踝/小腿/足部是否有伤病或不适 | injury_history | 多选卡（含"无"） | ✅ |
| | 每周能训练几天 / 每次能练多久 | available_days, available_min | 选项卡 + 自定义 | ✅ |
| | 主要训练场地 | terrain | 选项卡（公路/人行道/操场/跑步机/田径场） | ✅ |
| | 是否有哑铃/弹力带 | equipment | 多选 | ⭕ |
| 6 **运动风险筛查（安全必答）** | ACSM 预参与筛查三问（见 §5.5） | screening_answers | 结构化选项卡 | ✅ |
| 7 **目标确认** | 是否确认档案并生成计划 | confirmed | 卡片确认 | ✅ |

> **采集效率设计**：目标 3 分钟内完成（安全筛查 3 问以选项卡形式呈现，30 秒内可完成）。连续 3 问无实质输入时，AI 主动降低颗粒度（用范围选项而非精确数字）；允许用户随时"跳过"，跳过的字段走 AI 默认推算并在档案卡标注"AI 推测"。**第 6 段不可跳过**（安全项，见 §5.5）。

**AI 追问逻辑要点**
- 若用户输入的成绩与周跑量矛盾（如 10km 配速 4'00"/km 但周跑量 40km），AI 追问一次确认，不擅自改写
- 若用户无成绩，AI 用"周跑量 + 跑龄"反推区间并给建议值让用户确认；目标为半马/全马时，可参照 World Athletics 官方方法——先做一次 5km 测试，**在平均配速上加约 25–35 秒/km** 估算半马配速（WA 5km 25:00 → 半马约 5:30–5:35/km）
- 若用户有伤病史，AI 立即追问部位与是否痊愈，并在计划中降低相关强度、增加替代动作（见 §5.4 伤病适配）
- 若目标距离与基础矛盾（如从零基础直接选全马），AI 提示并给出中间路径（先半马）

#### A2 档案卡展示与确认

**页面**：档案确认页。

**结构**（四组卡片）：
1. **身体数据**：性别、年龄、身高、体重、BMI（带颜色评级）
2. **跑步基础**：跑龄、周跑次、周跑量、最长距离、当前 5km/10km 配速、舒适配速
3. **目标**：目标距离、目标日期、目标成绩、目标配速
4. **训练条件与健康**：可训练天数、单次时长、场地、器械、伤病史

**交互**：
- 卡片右上角「编辑」→ 进入该组的 AI 追问模式（增量追问，不重走全流程）
- 「AI 推测」字段带虚线下划线，点击可展开 AI 的推算依据
- 底部主按钮「确认档案，开始生成计划」
- 顶部提示："回答得越准，训练计划越贴合你"

**强度档定义（三锚点体系）**

本产品采用**主观用力（主）+ 配速偏移（副）+ 心率区间（第三轨，Demo 可选）**三锚点，用户按可得信息选其一即可。

| 强度档 | 代号 | 主观用词（爱尔兰田径协会口径） | 说话测试 | RPE(0–10) | 配速偏移（秒/km，相对目标配速 P） | 用途 |
| --- | --- | --- | --- | --- | --- | --- |
| 恢复跑 | Rcv | 极轻松 | 能唱歌 | 2–3 | P + 90 ~ P + 120 | 恢复、疲劳高时替代 |
| 轻松跑 | Easy | 轻松，呼吸放松 | 能持续对话 | 3–4 | P + 75 ~ P + 105 | 有氧基础（跑量主体） |
| 有氧跑 | Aero | 稍快 | 能说完整句但不能唱歌 | 4–5 | P + 55 ~ P + 75 | 稳态有氧（对应 B.A.A. "Aerobic Run"） |
| 长距离 | Long | 轻松 | 能对话 | 3–4 | P + 75 ~ P + 105 | 耐力、跑量基础 |
| 节奏跑 | Tempo | 受控用力 | 只能说短句 | 6–7 | P + 20 ~ P + 35 | 乳酸阈（质量课） |
| 间歇 | Interval | 接近最大努力 | 只能蹦词 | 7–9 | P − 10 ~ P + 10 | 最大摄氧量（质量课） |
| 比赛配速 | Race | 目标节奏 | 短句 | 7–8 | P ± 5 | 比赛节奏感（专项期） |

**强度分布原则（官方结构 + 分布原则约束）**

| 阶段 | 结构依据 | 强度分布约束 |
| --- | --- | --- |
| 准备/基础期 | B.A.A. 3 周准备 + 6 周基础；爱尔兰 1–4 周有氧基础与变速 | 轻松跑 ≥ 70%，长距离占跑量 15–20%，质量课 1 次/周 |
| 专项/进阶期 | B.A.A. 9 周马拉松专项；爱尔兰 5–9 周力量与速度 | 轻松跑 55–65%，质量课 1–2 次/周，长距离 15–20% |
| 状态提升期 | 爱尔兰 10–14 周专项与状态提升 | 引入比赛配速段；总强度课占比 ≤ 25% |
| 减量期 | B.A.A. 2 周减量；爱尔兰第 14 周 "TAPER WEEK" | 总量指数下降 41–60%，**强度与频次保持不变**（Bosquet 2007 荟萃分析结论） |
| 回撤周 | 爱尔兰 "Step-back weeks"（第 5、7 周等） | 每 3–4 周插入 1 周，总量 -20~30%，保留质量课与长距离 |

> **关键原则（引自 WA Advanced 计划原文）**："the best results rarely come from increasing both at the same time... we recommend focusing on one at a time: either run a little faster or run a little farther."
> → **同一周内不同时推进强度与总量**。这条直接写进计划引擎的冲突检测：若某周既要求跑量 +10% 又要求质量课提速，引擎自动把跑量增量回退。

#### B2 计划生成引擎

**输入**：跑者档案 + 目标配速 P + 目标类型 + 训练模板 + 伤病标记 + 可训练天数 + 安全筛查结果
**输出**：训练计划对象（plan + weeks + sessions）

**生成流程（8 步）**

| 步骤 | 动作 | 依据 / 规则 |
| --- | --- | --- |
| **0 安全闸门** | 读取 ACSM 预参与筛查结果。存在**绝对禁忌**或**需就医确认**项 → **不生成计划**，直接给出就医建议与"仅可做轻松走跑"的保守替代 | ACSM 预参与筛查（见 §5.5） |
| 1 | 选定模板 | 目标距离 + 距目标日期周数 + 当前水平 → T5-WA / T10-8W / T10-6W / T-HM / T-MAR-20 / T-MAR-16 | §B1 模板表 |
| 2 | 计算 P（目标配速） | 目标成绩 ÷ 目标距离；半马/全马无实测成绩时，用 WA 方法：5km 平均配速 **+25–35 秒/km** 估算 | WA 半马计划 p.3 |
| 3 | **可达性校验** | 提升幅度 / 精英级目标 / 强度跳跃 / 周跑量倒挂 / 伤病冲突五项校验（见 §1.3.3）。任一触发 → 生成"修正版计划"并说明原因 | §1.3.3 |
| 4 | 计算起始周跑量 | `起始周跑量 = 档案周跑量 × 0.9`；有伤病 × 0.85；可训练天数 <3 × 0.9；再对齐模板首周目标（B.A.A. Level One 首周 25 英里 / WA 半马 Beginner 首周 15km） | 模板原始结构 |
| 5 | 分配周内课次 | 按 available_days 排课；默认 周二/周四/周六 跑 + 周日 力量。若 days=2 → 保留质量课 + 长距离，取消第三跑 | 模板结构 |
| 6 | 逐周推进量 | 周跑量 ≤ +10%/周；每 3–4 周插 1 周回撤（-20~30%）；峰值后 2 周减量（-41~60%）；**单次长距离 ≤ 近 30 天最长 × 1.1** | §5.1 训练量规则 |
| 7 | 伤病/条件/安全适配 | 见 §5.4 伤病适配表；对每个 session 追加「适配说明」；有伤病史者强制加入髋/核心稳定训练 | §5.4、§5.5 |
| 8 | **冲突检测** | 同周内强度与总量同时推进 → 回退跑量增量（WA 原则）；课次时长 > available_min → 拆分或降级 | WA Advanced 原文 |

#### B3 计划总览页

**结构**
1. **头部卡**：目标成绩卡（当前成绩 → 目标成绩 → 预计达成周）
2. **周期进度条**：按模板周期长度的格子（5K 8 格 / 10K 8 格 / 半马 12 格 / 全马 20 格），当前周高亮，标注各周类型（准备/基础/专项/回撤/减量）
3. **周卡列表**：每周展开显示课次（类型徽标、目标距离、目标配速区间、RPE、当周量 vs 上周量 + 百分比）
4. **强度分布图**：环形或堆叠条
5. **适配依据卡**：AI 生成的上述说明
6. **CTA**：「确认计划，开始训练」/「重新生成」

**交互细节**
- 点击任一课次 → 课次详情页（B5）
- 「重新生成」→ 展示 2–3 个候选差异（如"更保守（跑量 -20%）"/"更激进（加 1 次间歇）"/"按标准"）供用户选，这是"个性化的边界由用户把控"的具体体现

#### B4 计划确认与变更 diff

- 确认页展示完整总览，主按钮「我确认，开始」
- 状态转为「执行中」，推送第一条课次提醒
- 后续每次 AI 调整计划时，同样走**变更 diff → 用户确认 → 生效**（见 E3）

```
本课目的：提高你的乳酸阈，让"舒服配速"的上限往后挪。
适配说明：上次长距离你反馈 RPE 6 且膝盖无不适，因此本课强度按模板执行。

① 训练说明（文字 + 要点）              ← 展开显示
② 练前动态热身（动作视频 + 文字要点）    ← 按课型推荐 5–8 分钟，可勾选完成
③ 主体：节奏跑（可跳过，直接进入记录）   ← 主按钮「开始跑步」
④ 练后静态拉伸（动作视频 + 文字要点）    ← 训练后推荐 5–10 分钟，可回看
```

#### B5.1 练前动态热身模块

**目标**：逐步提高体温和心率，活动跑步所需关节范围，激活臀部、小腿和躯干；不追求疲劳，不做长时间静态拉伸或强弹震动作。

**默认流程**：快走/慢跑 3–5 分钟 → 动态活动度 2–3 分钟 → 跑姿激活 1–2 分钟。轻松跑可采用 5 分钟版；节奏跑、间歇和比赛配速课采用 8–12 分钟版。天气寒冷时延长慢跑阶段，炎热时缩短并降低强度。

| 动作 | 建议剂量 | 教学要点 | 适用课型 | 教学视频 |
| --- | --- | --- | --- | --- |
| 快走/轻松慢跑 | 3–5 分钟 | 呼吸放松，逐步升温，不进入训练强度 | 全部 | `video_warmup_runner_01`（Mayo Clinic 跑者热身） |
| 踝绕环 + 提踵 | 每侧 10 次 + 15 次 | 动作慢而可控，脚掌三点支撑；不塌踝 | 全部 | `video_warmup_runner_02`（World Athletics 热身动作） |
| 摆腿（前后/左右） | 每侧 10 次 | 扶稳支撑物，骨盆保持正对前方，不甩动 | 质量课/长距离 | `video_warmup_runner_01`（Mayo Clinic 跑者热身） |
| 动态弓步 + 转体 | 每侧 6–8 次 | 前膝对准脚尖，幅度以无痛为准，躯干自然转动 | 质量课/比赛配速 | `video_warmup_runner_01`（Mayo Clinic 跑者热身） |
| 高抬腿 / 后踢腿 | 各 20 秒 × 2 组 | 小步幅、轻落地、身体直立；不追求抬腿高度 | 质量课/比赛配速 | `video_warmup_runner_02`（World Athletics 热身动作） |
| 渐进加速跑 strides | 4–6 次 × 15–20 秒，间隔慢走/慢跑 | 从轻松到约 70–85% 主观速度，不冲刺；出现疼痛立即停止 | 间歇/节奏/比赛配速 | `video_warmup_runner_02`（World Athletics 热身动作） |

**交互与安全**：每个动作展示时长/次数、分解要点、视频缩略图与「已完成」勾选；用户可跳过单个动作，但若跳过完整热身，开始质量课前弹出风险提示。疼痛、头晕、胸闷或动作导致的锐痛不属于正常热身反应，立即停止并进入 §5.5 安全流程。

#### B5.2 练后静态拉伸模块

**目标**：在完成 3–5 分钟低强度走/慢跑后，针对本课主要负荷肌群进行舒适范围内的静态拉伸。拉伸用于放松和活动度管理，不宣称能够单独预防伤病或治疗疼痛。

| 动作 | 建议剂量 | 教学要点 | 训练后重点 | 教学视频 |
| --- | --- | --- | --- | --- |
| 小腿腓肠肌拉伸 | 每侧 15–20 秒 × 2 | 后脚跟着地，脚尖朝前，身体前倾至轻微牵拉 | 全部，尤其间歇/坡跑 | `video_stretch_runner_01`（NHS 跑后拉伸） |
| 股四头肌拉伸 | 每侧 15–20 秒 × 2 | 膝盖并拢，骨盆保持中立，不要塌腰 | 全部 | `video_stretch_runner_01`（NHS 跑后拉伸） |
| 腘绳肌拉伸 | 每侧 15–20 秒 × 2 | 背部自然，髋部折叠；不弓背硬压 | 长距离/节奏跑 | `video_stretch_runner_01`（NHS 跑后拉伸） |
| 臀肌/梨状肌拉伸 | 每侧 15–20 秒 × 2 | 仰卧抱腿或交叉抱腿，保持呼吸，不拉扯膝关节 | 长距离/久坐用户 | `video_stretch_runner_01`（NHS 跑后拉伸） |
| 髋屈肌拉伸 | 每侧 15–20 秒 × 2 | 半跪，收紧腹部并轻收骨盆，避免腰部过伸 | 全部，尤其久坐用户 | `video_stretch_runner_02`（NHS 全身放松） |
| 大腿内侧拉伸 | 15–20 秒 × 2 | 坐姿脚掌相对，背部自然；不向下压膝盖 | 长距离/侧向动作较多 | `video_stretch_runner_01`（NHS 跑后拉伸） |

**执行规则**：每次训练结束先低强度走/慢跑 3–5 分钟，再进入静态拉伸；每个动作保持 15–20 秒，左右侧完成 1–2 组；牵拉感应为轻微至中等，不得出现锐痛、麻木或关节痛，不弹震、不屏息。用户存在伤病、近期手术、妊娠或不确定动作是否适合时，提示先咨询医生/物理治疗师。

### C. 真实 GPS 跑步

#### C1 训练准备页

- 检查项：定位权限（未授权 → 引导页）、GPS 信号强度（弱 → 提示"建议到开阔环境"）、电量优化提示
- 天气：Demo 不接天气 API，用占位卡（后续可接）

#### C2 GPS 实时记录（核心技术点）

| 项 | 规格 |
| --- | --- |
| 定位方式 | `定位精度最佳`（GPS + 网络辅助），持续定位，前台服务保活 |
| 采样频率 | 1 Hz（每秒一个点），保留时间戳、经纬度、精度、速度 |
| 距离计算 | Haversine 公式逐点累加；配速用最近 60 秒滑动窗口平滑 |
| 漂移过滤 | ① 单点瞬时速度 > 12 m/s 判为漂移丢弃；② 相邻点距离 > 50m 且时差 <1s 丢弃；③ 精度半径 > 30m 的点不参与配速计算但保留在轨迹中 |
| 自动暂停 | 连续 15 秒无有效位移 → 自动暂停计时（计步器式）；点击「继续」恢复；暂停段不计入用时 |
| 自动恢复 | 恢复移动后 5 秒自动恢复 |
| 手动暂停 | 支持，长按或点按按钮 |
| 中断处理 | App 切后台超过 30 秒 → 回来时提示「刚才有 X 分钟没有记录，已按暂停处理」 |
| 结束 | 手动结束 或 完成目标距离自动提示（不自动结束，避免用户误操作丢失数据） |

**实时界面元素**
- 大号配速（当前 30s 平均）`mm'ss"/km`
- 次要信息：总距离、总用时、平均配速、本次课次目标对比
- 轨迹图：实时描线（自定义 Canvas/地图 SDK）
- 配速区间条：显示当前配速落在哪个区间（轻松/节奏/间歇），越界变色
- 顶部：目标进度（例：节奏跑 20 分钟，已完成 12 分钟）
- 底部：暂停 / 结束 / 说话（语音输入反馈）

#### C3 AI 语音陪跑引导

**触发规则（Demo 简化为 5 类）**

| 触发 | 条件 | 话术示例 |
| --- | --- | --- |
| 开跑 | 训练开始 | "训练开始。今天是节奏跑，强度目标是'只能说短句'，配速大约 5'50 到 6'00。前 3 公里按轻松跑进入，别急着加速。" |
| 每公里 | 每满 1 公里 | "1 公里完成，用时 5 分 15 秒，平均配速 5'15"，比目标区间快了 12 秒，很好。" |
| 强度提醒 | 连续 90 秒**说话测试失败**（说不出完整句子）或配速超出区间 | "现在的强度偏快了，试着放松一点，能说完整句子就对了。"（**主用说话测试口径，配速为辅**） |
| 时间节点 | 每 5 分钟 | "已经跑了 15 分钟，配速稳定，继续保持。" |
| 收尾 | 距课次目标还有 2 分钟 / 用户点击收尾 | "还有 2 分钟，准备进入拉伸。别加速，按当前配速跑完。" |

**实现**：文案由 LLM 按课次上下文预生成（开始前一次性生成 8–12 条，按触发条件分桶），运行时由客户端按条件取用 → **保证跑动中零延迟、零网络依赖**，也避免 Demo 现场因网络波动卡壳。

**TTS**：调用语音合成服务；缓存为音频文件（Demo 中每种话术预生成，减小实时调用风险）。

- vs 计划：距离达成率、配速偏差、RPE 目标对比
- 主按钮「填写训练反馈」（不填则无法触发闭环）

### E. AI 总结与计划更新（闭环核心）

#### E1 AI 训练总结

**结构化模板**（每次一致的四段式）：

```
本次训练小结 · 节奏跑
① 数据回放：7.2km / 32'10" / 平均配速 4'28"，比目标区间快了 18 秒/公里。
② 做得好的地方：你在第 3 公里后配速波动从 25 秒收窄到 8 秒，节奏控制明显改善。
③ 需要注意：最后 2 公里 RPE 从 6 升到 8，主要因为右小腿发紧。
④ 下一步：下次长距离我会把总量减 1 公里，并加入 2 组单腿提踵。
```

**数据来源与生成边界**
- ①② 中所有数字**必须来自结构化数据**（后端计算后注入模板变量），LLM 只组织语言
- ③ 的判断依据是反馈表单的结构化字段 + 自由文本提取结果
- ④ **不自由发挥**：只能引用规则引擎给出的调整项集合（见 E2），LLM 负责解释为什么这么调
- 兜底：LLM 超时/失败 → 使用纯模板生成总结（数字仍正确，文字较机械），保证闭环不断

#### E2 规则引擎动态调整

**输入**：本次 feedback + 近 4 次课次记录 + 近 30 天最长距离 + 当前计划状态 + 伤病标记
**输出**：`AdjustmentSet`（结构化的变更集合 + 触发原因码）

**核心规则（按优先级判定，命中即停或叠加）**

| 优先级 | 触发条件 | 调整动作 | 原因码 | 依据 |
| --- | --- | --- | --- | --- |
| P0 | 疼痛评分 ≥ 7，或出现胸闷/头晕，或运动中出现 §5.5.2 中止信号 | **立即暂停计划**，下一课次替换为「休息 + 拉伸」，给出就医建议，不可拒绝 | `SAFETY_STOP` | ACSM 终止运动标准 |
| P1 | 疼痛评分 4–6，且部位为膝/踝/足 | 未来 3 天内取消质量课（间歇/节奏），改为轻松跑；增加关节稳定训练 | `PAIN_REPLACE` | §5.4；髋/核心训练可降 64% 伤风险 |
| P2 | 完成度 = 未完成 或 实际距离 < 计划 60% | 下次课次降级为恢复跑，总量 -30%，强度降 1 档 | `LOW_COMPLETION` | — |
| P3 | 连续 2 次 RPE ≥ 目标 RPE + 2 | 未来 1 周总量 -20%，质量课降为轻松跑 | `OVERREACH` | 过度负荷识别 |
| P4 | 连续 3 次完成度 = 完全完成 且 无疼痛 | 下周总量 +5%（**仍受 ≤+10%/周 约束**），质量课加 1 组间歇 | `PROGRESS_UP` | ACSM 渐进原则 |
| P5 | 实际距离 > 计划 115% | 提示并把下次同类型课次目标调回计划值 | `OVER_VOLUME` | — |
| **P6（最高优先级之一）** | **本次课次距离 > 近 30 天最长距离 × 1.1** | **拦截：该课次距离下调至近 30 天最长 × 1.1**；并提示"单次跑量突增是过度使用伤最直接的可控因素" | `SINGLE_SESSION_SPIKE` | Frandsen 2025《BJSM》：单次超近 30 天最长 10–30% → 伤风险 +64%；>100% → +128% |
| **P7** | 计划中某周同时出现"跑量 +10%"与"质量课提速" | 自动回退该周跑量增量，保留强度提升（**同一周只动一个变量**） | `DUAL_PROGRESSION_CONFLICT` | WA Advanced 原文；ACSM 先时长后强度 |
| P8 | 距目标日期 ≤ 14 天 | 进入减量期：总量按指数下降 **41–60%**，**强度与频次保持不变** | `TAPER` | Bosquet 2007《MSSE》荟萃分析；B.A.A. 2 周减量 |
| P9 | 距目标日期 ≤ 3 天 | 取消质量课，只保留轻松跑 + 短距离比赛配速段 | `RACE_WEEK` | B.A.A. 比赛周结构 |
| P10 | 距目标日期 ≤ 7 天 且 曾中断 > 2 周 | 切换保守版，赛事目标自动下调或建议改期 | `RACE_RISK_REVIEW` | §5.6 分支 |
| P11 | 用户反馈中含"没时间"/"受伤"/"生病"等关键词（LLM 提取） | 触发对应的 P1/P2 逻辑 + 文案层特殊处理 | `LLM_SIGNAL` | — |

> **规则设计的原则**：每条规则都必须在"宁可少练，不可受伤"与"仍要能出成绩"之间取得可解释的平衡。**P6 与 P7 是核心规则**——它们从**训练量数据本身**计算，属于专业训练教练才会做的事，也是竞品（标签匹配模板）不可能做的事。

**输出结构**

```json
{
  "adjustment_set": [
    {
      "type": "REPLACE_SESSION",
      "target": { "week": 3, "session_id": "w3s2" },
      "before": { "type": "tempo", "distance_km": 7, "pace": [285, 305] },
      "after":  { "type": "easy", "distance_km": 5, "pace": [330, 360] },
      "reason_code": "PAIN_REPLACE",
      "reason_text": "你这次右小腿疼痛评分 5，属于运动性不适区间。未来 3 天内我把节奏跑换成了轻松跑，并加上了单腿提踵。"
    },
    {
      "type": "MODIFY_SESSION",
      "target": { "week": 3, "session_id": "w3s3" },
      "before": { "distance_km": 8 },
      "after":  { "distance_km": 7 },
      "reason_code": "PAIN_REPLACE"
    }
  ],
  "safety_notice": null
}
```

**关键设计**：调整在**规则层**完成，LLM 只把 `reason_code` 翻译成人话。理由：
1. 训练逻辑正确性可回归测试（用历史数据回放跑测试用例）
2. 输出可解释——用户看得懂"为什么改"
3. 避免 LLM 给出运动损伤级的错误建议（这是本产品最大的风险项）

## 5. 训练引擎规则（详细规格）

### 5.1 训练量进阶规则（每条规则都挂权威依据）

| # | 规则 | 具体约束 | 依据 |
| --- | --- | --- | --- |
| R1 | 周跑量递增 | 每周 ≤ **+10%**；每 3–4 周插入 1 个**回撤周**（-20~30%，保留质量课与长距离） | ACSM《运动测试与处方》第 11 版渐进原则（先加时长后加强度，每次只动一个变量）；爱尔兰田径协会 "Step-back weeks"；B.A.A. "The step by step increase in daily and weekly mileage is designed to challenge you while also minimizing the risk of training too hard" |
| R2 | **单次长距离上限（最高优先级）** | 单次长距离 ≤ **近 30 天最长距离 × 1.1**；超过 1.3 直接拦截 | Frandsen 等 2025《BJSM》（Garmin RUNSAFE 队列，5205 名休闲跑者、58.8 万次训练、18 个月前瞻）：**单次跑量相对近 30 天最长距离**的增幅与伤病显著相关——10–30% 增幅伤风险 **+64%**，30–100% **+52%**，>100% **+128%**；而**周对周跑量增幅与伤病无显著关联** |
| R3 | 强度与总量不同时推进 | 同一周内不同时提高强度与总量；引擎检测到冲突时自动回退跑量增量 | WA Advanced 计划原文："the best results rarely come from increasing both at the same time... focus on one at a time"；ACSM 同原则 |
| R4 | 减量期 Taper | 赛前 **2 周**，总量**指数下降 41–60%**，**强度与频次保持不变** | Bosquet 等 2007《MSSE》荟萃分析（27 项研究）：2 周减量 + 41–60% 总量下降为最优策略；强度下调反而无益（0.33±0.14）；与 B.A.A. "2-WEEK TAPER PHASE"、爱尔兰第 14 周 "TAPER WEEK" 一致 |
| R5 | 单次时长上限 | 按 available_min 截断，超出则拆分为两次或降级为轻松跑 | ACSM FITT 的 Time 要素 |
| R6 | 有氧量下限 | 每周跑量换算 ≥ 每周 **150 分钟中等强度**（或 75 分钟高强度）活动量 | 《中国人群身体活动指南（2021）》；ACSM 一致。低于此值不生成质量课，先补有氧量 |
| R7 | 每周课次 | 默认 3 跑 + 1 力量；available_days=2 → 2 跑 + 1 力量（保留质量课） | WA（3 课/周）、B.A.A.（4–7 课/周按档位）、爱尔兰（3–4 课/周） |
| R8 | 力量与稳定性训练 | 每周 ≥1 次，赛后 1 天内；**有伤病史者强制保留**，内容以**髋外展肌 + 核心**为主 | Toresdahl 等 2025：髋外展/核心力量训练与**64% 更低**的跑步相关过度使用伤风险相关；2024 年 325 名新手跑者 RCT：髋与核心组过度使用伤发生率低 **39%**、"实质性"过度使用伤低 **52%**（踝足组无效）；《中国人群身体活动指南》每周 ≥2 天抗阻 |
| R9 | 休息日 | 每周至少 1 天完全休息；连续 2 天跑后必接休息或力量 | WA / B.A.A. 表结构；爱尔兰 Day 1/3/6 固定休息 |
| R10 | 长距离上限（按目标） | 5km/10km 计划：单次长距离 ≤ 计划最长 × 1.1；半马 12 周计划最长 18km（WA Intermediate）/16km（Beginner）；全马 20 周计划最长 16–18 英里（B.A.A. Level One） | 模板原始结构 + R2 规则 |

> **"≤10%/周"仅作为渐进控制参考**，实际执行时优先检查单次长距离突增、强度与总量是否同时推进，以及用户的反馈和风险信号。

### 5.2 课次结构模板

```
warmup（动态热身）→ main（主体训练）→ cooldown（静态拉伸）
```
- 热身时长：官方计划的统一做法是 **5–15 分钟轻松跑**（WA 5K 各课次统一 5–10 分钟；爱尔兰每个质量课统一 "WARM UP 15 MINS EASY"；B.A.A. 统一 "2–3 mile Warm Up"）
- 练前动态热身：先 **3–5 分钟快走/轻松慢跑**，再做摆腿、动态弓步、踝绕环、提踵、高抬腿/后踢腿；质量课可追加 4–6 次渐进加速跑。动作清单与剂量见 §B5.1。
- 练后静态拉伸：先 **3–5 分钟低强度走/慢跑**，再做小腿、股四头肌、腘绳肌、臀肌/梨状肌、髋屈肌和大腿内侧拉伸；每侧 15–20 秒 × 1–2 组。动作清单与安全规则见 §B5.2。
- 每个动作含：名称、时/次数、要点文字、演示视频资源 ID；视频采用官方机构或专业运动医学机构的公开教学内容，经审核后上传到产品媒体库。
- 权威依据：World Athletics《Warm-up Essentials》、ACSM《A Road Map to Effective Muscle Recovery》、NHS 跑后拉伸与放松课程、美国运动医学骨科协会（AOSSM）柔韧性与拉伸建议。
- 力量动作库：徒手深蹲、单腿臀桥、侧向弓步、**髋外展（侧卧抬腿）**、提踵、平板支撑、蚌式开合、靠墙静蹲、俯卧两头起

### 5.4 伤病适配表（补充循证结论）

| 伤病部位 | 计划影响 | 替代/补充动作 |
| --- | --- | --- |
| 膝（髌股疼痛） | 间歇中的下坡/跳跃取消；长距离上限 -20%；避免连续多日跑 | 靠墙静蹲、单腿臀桥、侧向弓步、**髋外展强化** |
| 踝（扭伤史） | 取消坡度/冲刺；加入平衡训练 | 蚌式开合、单腿站立平衡、提踵 |
| 小腿（跟腱/腓肠肌） | 暂停间歇与冲刺 1 周；增加离心提踵 | 单腿提踵慢速下放、台阶下落 |
| 足底筋膜 | 减少长距离，增加足底滚球 | 足底泡沫轴放松、短趾抓毛巾 |
| 髂胫束 | 长距离改平路，禁止下坡段 | 侧向弓步、**臀中肌/髋外展激活** |
| 无伤病 | 无特殊限制，但**仍保留每周 1 次髋/核心力量课**（R8 循证） | 髋外展 + 核心 |

> **安全底线 1**：任何部位连续 2 次反馈疼痛 ≥4，系统自动将该部位的进阶强度**永久降级**，并在总结中说明。
> **安全底线 2**：任何部位疼痛评分 ≥7 → 立即停止该部位的高强度内容并进入医疗建议流程（§5.5）。
> **安全底线 3**：髋/核心力量课在**有伤病史、BMI 偏高、全马目标**三种情况下**不可被"没时间"跳过**——引擎允许推迟到本周内其他日期，但不���许整周取消（取消则下周自动补回）。

### 5.5 运动风险筛查与训练中止标准（安全模块）

#### 5.5.1 训练前预参与筛查（ACSM 2015 算法 / 2018 修订，PAR-Q+ 简化版）

建档第 6 段以 3 道选择题完成，30 秒内可答完：

| 问题 | 选项 | 判定 |
| --- | --- | --- |
| Q1 你目前每周是否规律进行 ≥30 分钟中等强度运动、每周 ≥3 天、持续 ≥3 个月？ | 是 / 否 | 决定强度上限与是否需要医疗确认 |
| Q2 你是否存在以下任一症状或已确诊疾病？（可多选） | 运动时胸痛/不适（可放射至颈、下颌、手臂）/ 静息或轻微活动即气短 / 头晕或晕厥 / 夜间阵发性呼吸困难 / 踝部水肿 / 心悸或心动过速 / 间歇性跛行 / 已知心脏杂音 / 日常活动异常疲劳 | 命中任一项 → **转医疗确认流程** |
| Q3 你是否有运动相关肌肉骨骼问题，或近 6 个月内是否被医生要求限制活动？ | 是 / 否 | 命中 → 计划加保护性适配，仍需医生确认方可进入高强度课 |

**筛查结果 → 计划权限矩阵**

| 筛查结果 | 系统行为 |
| --- | --- |
| 低风险（Q1=是，Q2=否，Q3=否） | 正常生成计划，最高强度到间歇档 |
| 中风险（Q1=否 但无 Q2/Q3 症状） | 生成计划，但**首 2 周只出轻松跑 + 长距离**，强度课从第 3 周起解锁；总览页提示"前两周先建立基础" |
| 需医疗确认（Q2 命中任一项 或 Q3=是） | **不生成训练计划**；展示固定话术："检测到 [症状]，建议先就医确认后再开始训练。确诊无碍可回到这里继续。" 同时提供"仅走路/拉伸的保守方案"入口 |
| 全马目标 + 中风险 | 额外提示首次全马的风险量级（重大伤 8.9%、轻微伤 48.5%），并强制前置半马完成 |

> **产品判断**：一个跑者产品的安全模块做得好不好，直接决定它是"专业教练"还是"会害人的 App"。这一节是本产品与 Keep/咕咚最本质的差异之一——**Keep 不做训练前筛查，因为它不承诺专业训练**。

#### 5.5.2 训练中止标准（训练中与训练后）

**运动中立即停止并就医的信号**（ACSM 定义的"异常运动反应与终止运动的标准"：呼吸困难、关节痛、头晕、心率反应异常）
- 胸痛或压迫感，或疼痛放射至颈、下颌、手臂、背部
- 异常呼吸困难、明显气促（与强度不匹配）
- 头晕、眼前发黑、失去协调
- 心悸、心律不齐感
- 突发剧烈关节痛

**训练后反馈触发的计划级响应**

| 反馈信号 | 响应 | 依据 |
| --- | --- | --- |
| 疼痛 0–3 | 正常记录 | — |
| 疼痛 4–6（膝/踝/足） | 未来 3 天内质量课降级为轻松跑；增加关节稳定训练 | §5.4 |
| 疼痛 ≥7 / 出现胸闷、头晕 | 立即停止计划，替换为休息 + 拉伸 + 就医建议 | 安全底线 2 |
| 疼痛部位连续 2 次 ≥4 | 该部位进阶强度永久降级 | 安全底线 1 |
| RPE 连续 2 次高于目标 +2 | 下周总量 -20%，质量课降级 | 过度负荷识别 |
| 训练中出现"跑不动"的对话测试失败 | 语音教练立即降级为"降速跑或改走跑"，并记录到本次反馈 | 实时保护 |

#### 5.5.3 免责与合规

- 建档页、计划总览页、每次总结页固定位置展示：**"本产品提供训练信息与建议，不构成医疗建议。开始或修改运动计划前，请咨询有资质的医疗专业人员。"**（对齐 B.A.A. 与 ACSM 的免责口径）
- 不提供任何诊断、用药、康复治疗建议；识别到伤病类提问时统一走固定话术
- 健康与定位数据按敏感个人信息处理：最小化采集、可清除、可导出、单独授权（见 §8）

### 5.6 四类目标的周期设计

**周期长度与阶段直接对齐官方计划，不自造。**

| 目标 | 周期 | 阶段划分 | 课次/周 | 长距离峰值 | 强度重点 |
| --- | --- | --- | --- | --- | --- |
| 5km 提升 | 8 周 | 无命名阶段，按周推进；第 8 周为比赛周（**不安排训练课**） | 3 | 渐进跑 4km | 前 3 周跑走结合与节奏建立 → 第 6–7 周引入间歇与渐进跑 |
| 10km 提升 | 8 周 | 基础 3 周 → 进阶 2 周 → 强化 1 周 → 减量 1 周 + 测评 | 3–4 | 8–10km | 质量课 1 次/周（节奏跑为主） |
| 半马 | **12 周** | 无命名阶段（WA 原版）；本产品加注"基础 / 专项 / 减量"标签便于理解 | 3（高阶 4） | Beginner 16km / Intermediate 18km | 每周 1 次比赛配速段（2×1km → 5km+2km 递增）+ 长距离 |
| 全马 | **20 周** | **3 周准备 → 6 周基础 → 9 周专项 → 2 周减量**（B.A.A. 原版） | 4–6 | Level One 16–18 英里 / Level Two 18–20 英里 | 专项期引入"马拉松模拟跑"（起伏路：轻松 + MP 段 + 轻松），第 13–15 周出现 2×5 英里 @ MP |

**各目标的"达标判定"**

| 目标 | 计划结束时如何判定达成 |
| --- | --- |
| 5km/10km | 计划最后一周安排一次 5km 测速（或用比赛成绩），与基线对比 |
| 半马 | 比赛日成绩 vs 目标配速（BAA/WA 官方建议：分段配速，避免前快后慢） |
| 全马 | 同上；同时输出"完成度"评分（是否按配速完成、有无掉速过多） |

**降级与延期的分支**

| 情况 | 处理 |
| --- | --- |
| 训练中断 > 2 周 | 引擎回到"中断前最后完成的那一周"重新起算，并把该周跑量下调 20%（慢性负荷衰减，需重新适应） |
| 中断且距赛事 ≤ 4 周 | 切换到"保守版"：只保留轻松跑 + 一次短质量课，赛事目标自动下调或建议改期 |
| 出现伤病（§5.5） | 该部位强度永久降级；若距赛事 ≤3 周，建议改期或改为"完赛即目标" |

### 7.3 AI 能力设计

**Prompt 分层**

| 层 | 内容 | 变更频率 |
| --- | --- | --- |
| System | 角色设定（专业跑步教练）、安全边界（不诊断、不给医疗建议）、输出格式约束（JSON 或 Markdown 模板） | 低 |
| Domain | 训练术语表、强度区间定义、可用动作库、规则说明 | 低 |
| Runtime context | 跑者档案、当前计划、目标、本次课次、最近 4 次记录与反馈 | 高（每次调用注入） |
| Facts | 本次数值事实（时长、距离、配速、调整前后对比） | 高（强制注入，LLM 不得改写） |
| Guardrail | 安全规则（如疼痛 ≥7 强制停止，AI 不得劝阻） | 低（最高优先级） |

**关键约束**
1. 数值事实区用结构化 JSON 注入，并在 system 中声明「只能引用 facts 中的数值，不得自行计算或估算数值」
2. 涉及伤病/疼痛的问题走规则前置判断，LLM 只在规则允许范围内表达
3. 所有 JSON 输出使用 schema 校验，失败则重试 1 次，仍失败走模板兜底
4. 温度设置偏低（0.3–0.5），保证同一输入输出一致

**Demo 稳定性保障**
- LLM 调用失败/超时（设 20s 超时）→ 模板兜底文案（数值仍由引擎算，保证正确）
- 语音话术**全部预生成并缓存**，跑动中不依赖网络
- 提供「演示模式」开关：一键将 LLM 输出替换为录制好的脚本，保证现场演示 100% 成功（面试场景必备）

### 13.5 规则引擎的循证依据（答辩可直接引用）

| 规则 | 循证结论 | 文献 |
| --- | --- | --- |
| 单次长距离 ≤ 近 30 天最长 × 1.1 | 单次跑量相对近 30 天最长距离的增幅与过度使用伤显著相关：10–30% → 风险 +64%；30–100% → +52%；>100% → +128%（翻倍）。**周对周跑量增幅与伤病无显著关联**；ACWR 无预测价值 | Frandsen P, et al. "How much running is too much? Identifying high-risk running sessions in a 5200-person cohort study." *British Journal of Sports Medicine*, 2025;59:1203–1210（Garmin RUNSAFE 队列，5205 人 / 58.8 万次训练 / 18 个月前瞻） |
| 髋/核心力量课每周 1 次、不可跳过 | 髋外展/核心训练与 **64% 更低**的跑步相关过度使用伤风险相关；2024 RCT（325 名新手）：髋与核心组过度使用伤低 **39%**、"实质性"过度使用伤低 **52%**；踝足组无获益 | Toresdahl et al., 2025；2024 年 RCT |
| 赛前 2 周减量 41–60%，强度不减 | 2 周减量 + 总量指数下降 41–60% 为最优策略（效应量 0.59±0.33 / 0.72±0.36）；**强度下调无益**（0.33±0.14）、频次下调无益（0.35±0.17） | Bosquet L, et al. "Effects of tapering on performance: a meta-analysis." *Medicine & Science in Sports & Exercise*, 2007;39(8):1358–1365（27 项研究） |
| 每周 ≤ +10%，每 3–4 周回撤周 | 10% 规则本身从未在对照试验中验证（Buist 2008 RCT 无获益），但**渐进超负荷、每次只动一个变量、周期化安排回撤周**是 ACSM 与各官方计划的共同原则 | ACSM《Guidelines》第 11 版；Buist et al., 2008；爱尔兰田径协会 step-back week |
| 强度与总量不同时推进 | "the best results rarely come from increasing both at the same time... focus on one at a time" | World Athletics 半马计划 Advanced 版原文 |
| 首次全马风险提示 | 首次全马跑者重大伤 **8.9%**、轻微伤 **48.5%**；纽约马拉松队列训练期受伤 **38.4%**、比赛日 **14.1%**、总体 **42.6%**，过度使用伤随训练推进上升 | Toresdahl et al., 2020；McGrath, Fontana & Toresdahl, *BMJ Open Sport & Exercise Medicine*, 2024;10:e001766（n=1049） |
| 训练前风险筛查 | ACSM 预参与筛查算法（2015 版 / 2018 修订）：规律活动史、症状与疾病清单、绝对与相对禁忌症、训练中止标准 | ACSM Guidelines 11th ed.；Riebe et al., 2015 |
| 长距离一律轻松跑 | 12 周半马计划中所有长距离均标注 easy；高级档最后一周长距离由 16km 主动降至 10km | World Athletics 半马官方计划 |
| 训练中语音提醒的强度口径 | 用"能否连贯说话"而非绝对配速作为强度锚点，更适配业余跑者 | 爱尔兰田径协会；中国人群身体活动指南 |
