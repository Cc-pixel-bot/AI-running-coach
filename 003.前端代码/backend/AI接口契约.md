# 智程 AI 接口契约

## 1. 文档目的

本文档定义智程 Demo 的两个核心 AI 接口：

1. 根据跑者档案和 10 公里训练模板生成训练计划；
2. 根据实际训练数据和用户反馈调整后续训练计划。

本文档定义输入、输出、处理状态和校验规则，作为后续大模型接入与前后端联调的统一依据。

## 2. 统一约定

### 2.1 登录要求

两个接口都要求用户已经登录，使用当前项目已有的请求头：

```text
Authorization: Bearer 登录后得到的令牌
```

后端根据登录用户读取对应的档案和计划，用户身份以登录令牌为准。

### 2.2 当前 Demo 范围

- 目标距离固定为 10 公里；
- 训练周期固定为 8 周；
- 输入字段采用当前建档页已有字段；
- 风险筛查需要医疗确认时，返回“已拦截”状态和安全提示。

### 2.3 通用状态

接口返回结果统一包含：

| 字段名 | 中文含义 |
| --- | --- |
| `success` | 本次请求是否成功 |
| `status` | 当前处理状态 |
| `message` | 给前端展示的中文说明 |

`status` 使用以下状态值：

| 状态值 | 中文含义 | 使用场景 |
| --- | --- | --- |
| `generating` | 正在生成 | 大模型正在生成计划 |
| `analyzing` | 正在分析 | 大模型正在分析训练反馈 |
| `completed` | 已完成 | 已生成并通过校验 |
| `blocked` | 已拦截 | 风险或档案问题阻止继续 |
| `failed` | 处理失败 | 模型调用或校验失败 |

## 3. 初始训练计划生成接口

### 3.1 接口地址

```text
POST /api/ai/plans/generate
```

### 3.2 前端提交内容

前端提交当前建档页已经采集的跑者档案，字段名称与现有代码保持一致：

| 字段名 | 中文含义 | 来源 |
| --- | --- | --- |
| `gender` | 生理性别 | 建档页 |
| `birthYear` | 出生年份 | 建档页 |
| `heightCm` | 身高，厘米 | 建档页 |
| `weightKg` | 体重，千克 | 建档页 |
| `runsPerWeek` | 最近每周跑步次数 | 建档页 |
| `recentRunsPerWeek` | 最近每周跑步次数的兼容字段 | 当前档案兼容字段 |
| `weeklyKm` | 近 3 个月平均每周跑量 | 建档页 |
| `longestRunKm` | 最近最长连续跑距离 | 建档页 |
| `best10kPace` | 10 公里最好成绩换算出的配速，单位为秒/公里 | 建档页 |
| `easyPace` | 平时舒服慢跑配速，单位为秒/公里 | 建档页 |
| `targetType` | 训练目标类型 | 建档页 |
| `targetDistance` | 目标距离，当前为 `10K` | 建档页 |
| `targetTime` | 目标完成时间，单位为秒 | 建档页 |
| `targetPace` | 目标配速，单位为秒/公里 | 当前档案计算字段 |
| `availableDays` | 每周可训练天数 | 建档页 |
| `availableMin` | 单次最大训练时长，单位为分钟 | 建档页 |
| `terrain` | 主要训练场地 | 建档页 |
| `injuries` | 伤病和不适选择 | 建档页 |
| `screening` | 三项风险筛查答案 | 建档页 |
| `riskLevel` | 风险等级 | 后端筛查结果 |

请求示例：

```json
{
  "profile": {
    "gender": "男",
    "birthYear": 1995,
    "heightCm": 175,
    "weightKg": 68,
    "runsPerWeek": 3,
    "recentRunsPerWeek": 3,
    "weeklyKm": 20,
    "longestRunKm": 8,
    "best10kPace": 390,
    "easyPace": 420,
    "targetType": "improve_10k",
    "targetDistance": "10K",
    "targetTime": 3300,
    "targetPace": 330,
    "availableDays": 3,
    "availableMin": 60,
    "terrain": "道路",
    "injuries": [],
    "screening": {
      "q1": "否",
      "q2": ["none"],
      "q3": "否"
    },
    "riskLevel": "low"
  }
}
```

### 3.3 后端提供给 AI 的模板内容

后端从模板库读取以下内容，作为 AI 生成计划的训练框架：

| 内容 | 中文含义 |
| --- | --- |
| `id` | 模板编号 |
| `name` | 模板名称 |
| `targetDistance` | 模板目标距离 |
| `durationWeeks` | 模板周期 |
| `runsPerWeek` | 模板建议跑步次数 |
| `sessionsPerWeek` | 模板建议总课次 |
| `goalTypes` | 适用目标 |
| `volumePolicy` | 训练量变化边界 |
| `blueprint` | 8 周训练结构 |

模板用于限定训练方向，AI 按模板阶段、回撤周和周期收尾减量安排生成每日训练。

### 3.4 AI 生成的计划内容

AI 返回的计划结构与当前前端计划页面保持一致。

计划整体字段：

| 字段名 | 中文含义 |
| --- | --- |
| `id` | 计划编号 |
| `templateId` | 使用的模板编号 |
| `templateName` | 使用的模板名称 |
| `targetDistance` | 目标距离 |
| `goalPace` | 目标配速，单位为秒/公里 |
| `goalTotalSec` | 目标完成时间，单位为秒 |
| `goalDerivedFrom` | 目标配速的计算依据 |
| `status` | 计划状态 |
| `currentWeek` | 当前周次 |
| `totalWeeks` | 总周数，当前为 8 |
| `startDate` | 计划开始日期 |
| `weeks` | 8 周训练内容 |
| `zoneDistribution` | 强度分布 |
| `totalKm` | 全周期计划总跑量 |
| `adaptationSummary` | 个性化调整说明 |
| `screening` | 风险筛查结果 |
| `sourceRefs` | 模板参考来源 |
| `createdAt` | 计划生成时间 |

每个训练课次包含以下内容：

| 字段名 | 中文含义 |
| --- | --- |
| `id` | 课次编号 |
| `week` | 所属周次 |
| `dayOffset` | 一周中的日期位置 |
| `dayLabel` | 页面显示的训练日 |
| `status` | 课次状态 |
| `type` | 训练类型 |
| `level` | 强度等级 |
| `title` | 训练名称 |
| `distanceKm` | 训练距离 |
| `durationMin` | 训练时长 |
| `intensity` | 强度和配速信息 |
| `description` | 训练说明 |
| `structure` | 主体跑步训练内容 |
| `preRunWarmup` | 练前动态激活结构，包含标题、总时长和动作列表 |
| `mainRun` | 主体跑步结构，包含类型、距离、时长、配速和训练结构 |
| `postRunStretch` | 练后静态拉伸结构，包含标题、总时长和动作列表 |
| `warmup` / `cooldown` | 兼容字段；保存和旧版前端读取时分别对应两组结构中的 `exercises` |
| `adaptationNote` | 个性化调整说明 |
| `coachQuote` | 智程训练提示 |

模型生成阶段，`preRunWarmup.exercises` 和 `postRunStretch.exercises` 只返回动作编号数组。后端根据动作编号从动作注册表补齐中文名称、建议剂量和执行要点，并生成前端及数据库兼容字段。这样模型负责结合课次选择动作，动作说明始终使用系统核定内容。

训练类型只能使用当前前端支持的值：

```text
easy       轻松跑
recovery   恢复跑
long       长距离跑
tempo      节奏跑
interval   间歇跑
race       目标配速跑
strength   力量训练
```

### 3.5 计划生成校验

后端保存计划前会检查：

- 目标距离是 10 公里；
- 周期正好 8 周；
- 每周训练次数不超过用户可训练天数；
- 单次训练时长不超过 `availableMin`；
- 长距离不明显超过 `longestRunKm` 的安全上限；
- 周跑量变化符合模板的 `volumePolicy`；
- 回撤周确实降低总量；
- 周期收尾减量周不增加训练负荷；
- 伤病情况下没有安排不适合的质量课；
- 风险需要医疗确认时没有生成正常计划；
- 每个训练课次都具备页面所需字段；跑步课次必须同时具备 `preRunWarmup`、`mainRun`、`postRunStretch`。
- 动作 ID 必须存在于后端动作注册表，且与课次训练类型匹配；动作名称、剂量和说明由后端注册表补齐；伤病场景不得选择被禁用的高负荷热身动作。

校验失败时返回校验原因，并进入失败处理流程；通过校验的结果进入保存流程。

## 4. 动态调整接口

### 4.1 接口地址

```text
POST /api/ai/plans/adjust
```

### 4.2 前端提交的实际训练数据

训练执行结束后，当前前端已经记录以下字段：

| 字段名 | 中文含义 |
| --- | --- |
| `id` | 本次训练记录编号 |
| `sessionId` | 对应的计划课次编号 |
| `sessionTitle` | 原定训练名称 |
| `week` | 所属周次 |
| `date` | 训练日期 |
| `type` | 原定训练类型 |
| `actualDistanceKm` | 实际完成距离 |
| `actualDurationSec` | 实际训练时长，单位为秒 |
| `avgPace` | 实际平均配速，单位为秒/公里 |
| `bestPace` | 实际最快配速，单位为秒/公里 |
| `pauseCount` | 暂停次数 |
| `zoneSeconds` | 各强度区间累计时间 |
| `laps` | 分段记录 |
| `points` | GPS 轨迹点 |

### 4.3 前端提交的用户反馈

当前反馈字段为：

| 字段名 | 中文含义 |
| --- | --- |
| `actualDistanceKm` | 用户修正后的实际距离 |
| `actualDurationMin` | 用户修正后的实际时长，单位为分钟 |
| `completion` | 完成度 |
| `rpe` | 主观用力程度 |
| `painScore` | 疼痛评分 |
| `painParts` | 疼痛部位 |
| `feel` | 训练后的身体感受 |
| `note` | 用户文字反馈 |

### 4.4 AI 动态调整输入

后端将以下内容一起提交给 AI：

```text
1. 本次原定训练课次；
2. 本次实际训练数据；
3. 本次用户反馈；
4. 当前完整训练计划；
5. 最近训练记录；
6. 当前跑者档案；
7. 后续尚未完成的训练课次。
```

### 4.5 AI 动态调整输出

返回结果与当前前端的调整页面保持兼容：

| 字段名 | 中文含义 |
| --- | --- |
| `plan` | 调整后的完整计划 |
| `adjustments` | 调整项目列表 |
| `safetyNotice` | 安全提示，无安全提示时返回 `null` |
| `reasonCodes` | 调整原因编号 |

每个 `adjustments` 项目包含以下内容：

| 字段名 | 中文含义 |
| --- | --- |
| `id` | 调整编号 |
| `type` | 调整类型 |
| `target` | 被调整的周次或课次 |
| `before` | 调整前内容 |
| `after` | 调整后内容 |
| `reasonCode` | 调整原因编号 |
| `reasonText` | 面向用户的中文调整原因 |

调整类型只能使用当前前端支持的类型：

```text
REPLACE_SESSION  替换某一课次
MODIFY_SESSION   修改某一课次
MODIFY_WEEK      修改某一周
MODIFY_PLAN      修改整体计划
```

### 4.6 动态调整校验

后端保存调整结果前会检查：

- 调整目标确实存在于当前计划；
- 调整前内容与数据库中的当前计划一致；
- 调整后的训练仍然是 10 公里、8 周计划；
- 调整后符合单次训练时长限制；
- 调整后符合长距离安全上限；
- 疼痛或安全风险出现时执行降负荷或恢复安排；
- 用户未完成训练时优先安排恢复或降低后续跑量；
- 无需调整时返回空的 `adjustments` 列表；
- 调整原因统一使用中文。

## 5. 错误状态

| HTTP 状态 | 中文含义 | 前端处理 |
| ---: | --- | --- |
| `400` | 输入字段不完整或格式错误 | 提示用户补充或修正信息 |
| `401` | 登录失效 | 返回登录页 |
| `409` | 风险筛查触发安全拦截 | 展示安全提示和下一步处理建议 |
| `422` | AI 返回内容不符合计划要求 | 后端拒绝保存并记录原因 |
| `503` | 大模型暂时不可用 | 展示重试提示并保留当前计划 |

## 6. 数据保存约定

### 初始计划

AI 输出通过后端校验后，保存为当前用户的新计划；生成失败时保留当前计划并记录失败原因。

### 动态调整

调整结果先作为待确认结果展示给用户。用户点击“采纳调整”后更新后续计划；用户选择“保持原计划”时保留当前计划，并保存本次调整记录。

涉及的数据库保存内容包括：

- AI 请求摘要；
- AI 返回结果；
- 后端校验结果；
- 当前计划版本；
- 调整前内容；
- 调整后内容；
- 用户最终选择；
- 生成或调整时间。
